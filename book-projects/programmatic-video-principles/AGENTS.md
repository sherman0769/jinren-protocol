# Project instructions — 程式如何變成影片

## 任務身份

你接手的是原理書，不是生成新電影、推銷模型、整理英文百科或編寫單一框架手冊。先讀 `00_START_HERE.md`、`book.json`、`work.json`、`CONTEXT/DECISIONS_AND_BOUNDARIES.md`。

## 不可稀釋的寫作規則

1. 全文使用繁體中文與臺灣常用詞。先提出可想像的問題，講清楚動作與因果，再給中文名稱及括號內英文。不得用尚未教過的術語解釋新術語。
2. 每個核心概念要有「生活理解 → 比喻邊界 → 精確定義 → 最小例子 → 失敗例子 → 檢查方法」。保留正式英文以便查文件，不把讀者推去自行讀英文才懂本章。
3. 公式逐一說明字母、單位、範圍、取樣時點；先算一組數字再談抽象表示。讀者可先跳過推導，不能被要求跳過原理。
4. 程式碼標明可執行／偽程式；可執行例子提供檔名、環境、輸入、指令、預期輸出、故障處理及測試紀錄。不貼長程式代替教學。
5. 純文字敘述不宣稱任一模型「最好」；變動中的工具功能、名稱、API 與價格需當時查官方來源，放可更新附錄。本書不把社群炫技影片視為嚴謹模型評測。
6. 原理簡化不得變成錯誤。逐條遵守 `STYLE_GUIDE/TECHNICAL_ACCURACY.md`。

## 證據與案例

本包只有案例 QA、兩支影片的本次 FFprobe 紀錄及四張截圖。原案報告中的 70 項測試是歷史報告，不是你本輪執行。Python／Cairo 是原案報告記載；Remotion 是先前構想，不得寫成已採用。正式聲線未完成，eSpeak 是工程聲音。未讀原碼不得編造函式或精確參數。新例子一律標「教學重建」，不是反編譯或原案摘錄。

## 工作方法

遵守現有系統與專案規約；不要覆寫使用者未提交的修改。現有書籍母專案不明時，保留本資料夾作獨立交接；不得硬寫 D 槽路徑、掃描家目錄祕密、上傳私人素材、部署或付費調用。

從驗證環境與樣章開始；依 `OUTLINE/chapter_plan.json` 的依賴順序寫作。下一批預設是前言與第 1～3 章完整初稿。之後逐批完成全書；不要只重寫規劃。每章走撰稿、技術審查、初學者審查、引用查核、修稿流程。同一模型可以分角色審查，但不能稱成獨立專家驗收。

正式書稿寫入 `MANUSCRIPT/chapters/`；參考樣章留在原處。新產出不得在尚未完成審查時標記 final。已完成任務更新 `work.json`、章節狀態及 `qa/` 的實際證據。中斷前保存下一個可執行步驟與阻礙，不假裝離線後仍會繼續。

## 核心檢查命令

```sh
python scripts/validate_package.py
python -m unittest discover -s tests -v
python examples/build_examples.py
python scripts/lint_manuscript.py
```

`lint_manuscript.py` 是人工審查提示器，不會證明文字正確或初學者真的懂。首輪執行若沒有正式書稿，應回報「尚無正式書稿」，不是「全書通過」。

## 執行權限

允許：本資料夾內閱讀、撰寫、離線測試與本地示範輸出。需要額外明確授權：付費聲音／模型 API、外部發布、修改母專案架構、刪除資料、大範圍重構。絕不包含或分享 API 金鑰、聲紋樣本、字型檔。
