# 技術校正表｜避免好懂卻講錯

下列是本書必須保留的邊界。括號來源編號對應 `RESEARCH/sources.json`；例中的推導由本書自行說明，不是從來源複製段落。

| 容易說過頭的簡化 | 本書必須採用的精確說法 |
|---|---|
| 影片就是儲存很多 PNG | 概念上可看作按時間採樣的影格；實際可透過記憶體或管線編碼，不必把每張圖落盤。壓縮內部也不一定儲存完整獨立圖片。（S01、S08） |
| 影片永遠固定 fps | 本書示範選固定幀率便於推導；真實媒體還可能有可變幀率與各自時間戳。（S08） |
| 最後一張是總幀數 | 從零編號時最後一張為 N−1；N/fps 是片段持續時間，最後取樣時刻為 (N−1)/fps。（S01） |
| 動畫只能是 F(t) | 這是很適合離線渲染的表達；狀態式模擬需要初始狀態、固定步長或重播／緩存策略才能可靠取得指定時刻。（S18） |
| 插值就是緩動 | 插值在值之間求值；緩動重映射時間進度。先教兩者各自的輸入輸出。（S16） |
| 彈簧一定會彈 | 阻尼與參數不同可能不出現反復振蕩；示範聲明所用模型與條件。（S18 為模擬時間參考，彈簧方程須在成稿時另查原始力學來源） |
| 設 Seed 就永久一樣 | 還涉及演算法、調用順序、字型、軟硬體和浮點行為；不能保證跨環境 MP4 字節完全相同。（S04） |
| Noise 都是有規律的亂 | 噪聲有多種；需區分獨立隨機、平滑程序噪聲與本文自訂的正弦變化。（S19） |
| 曲線進度均勻就是等速 | 均勻參數不是均勻弧長；要等速走曲線需處理距離與參數的對應。（S03） |
| 一字一個字形 | 編碼、感知字元分段、字形與排版不是必然一對一。（S11、S15） |
| 圖上兩點近就相關 | 除非定義與資料支持，否則距離只是佈局結果。（S12） |
| 三維只是多一個 z | 真正出畫還涉及變換、相機、投影、裁切與遮擋。（S07） |
| Shader 都在算像素 | 著色器有不同階段；WebGL 的 shader 指頂點和片段，計算著色另依平台。片段也不嚴格等於最終像素。（S06） |
| GPU 一定比較快 | 要考慮工作型態、資料搬移、硬體和實現；本書用實測比較，不給無基準百分比。 |
| MP4 就是 H.264 | MP4 是容器；H.264 是影片編碼標準；渲染、編碼、封裝、混音要分開。（S08） |
| 聲音也每秒三十格 | 音訊有自己的取樣率，以時間與影格對應。（S10） |
| 換聲音不用動圖 | 只有新音訊適合既定時間窗且內容／事件不變時可能只換軌；否則須重排或局部重渲染。原案正好可說明這個限制。（案例 QA） |
| 自動測試通過就完成 | 完整解碼、視覺檢查、發音聽審、審美與目標理解各有不同證據。不可由一個測試數字推斷全部品質。（S08、案例 QA） |
| 動畫測驗證明某模型全面更強 | 視覺作品同時受提示、環境、模板、重試、美術和選片影響；只能支持明確範圍內的觀察，不能代替完整模型評測。 |

本頁不把未查核的參考連結包裝成充分證據。成稿若加入更深入的物理、色彩或音訊標準，應補獨立來源與實際實驗。
