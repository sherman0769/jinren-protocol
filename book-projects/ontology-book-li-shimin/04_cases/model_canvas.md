# 一頁業務模型工作表

這是本書整理的教學工作表，不是產業標準。

## 已填例：報名與剩餘名額

目的：回答某一班在指定資料時間下還有多少名額，並辨識能否進一步操作。
範圍：人、課程、班別、報名、付款；不含薪資、出席、健康資料與退款資格規則。

核心概念：課程可重複開班；名額屬於班別；報名是人與班別的連接；確認與付款分開；講師是一種情境角色。

必答問題：CQ01–CQ04、CQ06、CQ11、CQ12。資料來源：SNAP-001。識別規則：以穩定 ID 連接，不以姓名合併。時效：快照答案明確帶時間；操作必須重查。

規則分工：概念層定義 confirmed 的意思；資料驗證層檢查容量與連結；統計採完整報名清單；執行端防止超賣；授權層決定誰可改。未知情況：沒有教室、付款不完整、未定義退款資格。

最小替代：若只處理這幾張穩定表，先以資料字典、SQL 查詢與受控 API 完成。只有出現跨來源語意對齊與重用需求，才檢驗更形式化本體是否值得。

成功條件：回答可追溯、同名不誤合併、未知不亂補、班別不混算、沒有授權不操作。失敗與停止條件：模型維護負擔超過新增價值，或較簡單方案已滿足任務。

## 遷移作業：攝影接案團隊

用相同問題自行定義「專案、委託者、照片、檔案版本、交付、驗收」。必須區分原始檔、修圖稿與核准交付版；不要把「已傳出」當成「客戶已驗收」。至少提出六道能力問題、一個未知狀態、一項授權限制與一個不使用本體的方案。
