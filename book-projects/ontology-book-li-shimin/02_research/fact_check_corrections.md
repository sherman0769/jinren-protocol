# 正式寫作前的概念校正

以下校正覆蓋本次交接前對話中的簡化說法。這是本輪重新核對後的內容基準；不能因舊對話說過，就視為已查證。

| 容易誤寫的句子 | 正式稿可使用的方向 | 證據／性質 |
|---|---|---|
| 沒有本體，AI 就完全不懂企業、不能做事 | 沒有正式本體仍可能以清楚文件、綱要、查詢工具與流程完成任務；是否需要更明確建模由任務判斷 | R18；本書架構判斷 |
| LLM 只是算力或聊天引擎 | 它能進行語言處理、生成與工具使用相關任務，但可靠企業運作仍依賴外部系統設計 | R09、R18；不得抹平模型能力 |
| RAG 只檢索文件 | 文件檢索是常見做法；廣義檢索增強可連接多種外部知識，圖式方法也是一條路 | R09、R24 |
| 本體只含規則，知識圖譜只含真實資料 | 是入門分工的簡化，兩者實際範圍可重疊；本體也可含個體事實 | R04、R08 |
| 所有關係都是分類階層 | 「是一種」「參加」「支付」「授課」語意不同；不能全部用父子階層表示 | R02、R04、R06 |
| 講師一定是員工 | 本書案例允許外聘與多重角色；除非特定公司明確限定，不作普遍子類公理 | 本書假設模型邊界 |
| 本體一定包含權限、行動與交易系統 | 有些產品把它們整合；這是平台設計，不是通用本體定義 | R01、R14、R16 |
| OWL 寫了必填與數量，就會自動拒絕壞資料 | 形式語意、資料驗證及應用強制執行分開；未知與不存在不可混淆 | R04、R05 |
| 推理一致就代表現實正確 | 一致性是對已接受前提的性質，不能替原始事實背書 | R04；對形式推理語意的直接解讀 |
| GraphRAG 就是更好的 RAG | 方法、資料與題型影響結果，要有可比基準；不把局部成績擴成通則 | R10、R11 |
| MCP 接通後，自動解決本體、權限與安全 | MCP 提供連接規範；業務語意與安全執行需要另外實作 | R17 |
| 有共同本體，就應讓所有 Agent 看相同資料 | 共享定義不等於相同資料授權；可使用分權視圖與局部領域對應 | R17、R25；本書架構綜合 |
| 一家公司只能有一個完全統一的模型 | 不同部門可能需要不同但可映射的模型；需說明邊界及對應 | R25 |
| 把本體連上最新資料就等於數位分身與因果模擬 | 可支撐營運表徵；模擬另需動態狀態、假設與適當模型 | R22；不能由圖上關聯推出因果 |
| AI 自動生成概念，就完成企業本體 | 需分開候選抽取、領域適切性、形式一致、實際任務效用與維護責任 | R12、R13、R21 |
| Microsoft 功能現在已是正式產業標準 | 本輪文件仍標示 preview，且產品地位不等於標準地位 | R14、R15，查閱 2026-09-28 |
| 兩家企業都在做，所以是主流必然方向 | 只能說有這些公開實作；普及程度、效益與產業共識要另找證據 | 研究方法限制 |

## 不得沿用的未核定材料

使用者最初提供的書摘沒有可核對的版本、頁碼與完整上下文，不能寫成「李開復在某頁說」。它是選題觸發材料，不是本書現有正式引文。

前段對話曾提到未經本輪核定的 2026 系統性文獻回顧及 DOI。這些未列入研究來源；Codex 不可直接復用，也不可宣稱已讀。要使用時先核對篇名、作者、出版狀態與全文內容，必要時排除。

## 與新產品或新論文有關的措辭

「目前」「最新」「已支援」「正式版」必須配查閱日期與版本。不能靠舊對話、模型記憶或 arXiv 編號推定日期。R11 是一個具體提醒：已查到 v3，就不能沿用 v1 的作者與數值而不說明。
