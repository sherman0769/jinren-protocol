## 唯一任務

分析跨 Agent 協作、跨部門映射及營運數位分身的可行方向與條件。

## 核心問題、答案與觀點

問題：很多 Agent 工作時，必須共用一份完全一致的巨型本體嗎？

答案與本章觀點：可共享必要定義、識別方式與契約，同時保留部門語境及不同權限；動態模擬還需要額外的狀態與模型。

## 讀者前後轉變

閱讀前：以為全部 Agent 接同一張圖，就能自然協作與預測企業未來。

閱讀後：能區分共享語意、任務協調、權限視圖與模擬能力。

## 摘要與論證順序

1. 教務、客服、帳務三種角色共同處理一個問題。
2. 說明同一個學員在不同任務中的合理定義差異。
3. 以限界情境與映射取代強迫全部統一。
4. 比較 Agent 記憶與長期概念模型。
5. 提出三條條件式方向：受治理分析、受控行動、營運模擬；逐條列缺少的配套。

## 案例與情境

客服可看到報名結果而看不到付款工具憑證；多個 Agent 共用班別識別碼不代表共享全部個資。

案例均為明確假設；作者真實經驗沒有確認前，不得改寫成「我曾經……」。

## 可形成的工作表或模型

共用契約、分域定義、分權視圖；用案例說明，不命名新產業標準。
