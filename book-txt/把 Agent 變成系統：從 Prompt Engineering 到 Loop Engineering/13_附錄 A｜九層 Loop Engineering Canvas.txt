附錄 A｜九層 Loop Engineering Canvas

用一張畫布，把 Agent 從「能不能做」轉成「怎麼可靠地做」。

這份 Canvas 是本書整合十項研究後提出的實務工作表，不是既有產業標準。使用時，不必每一格都填滿；應依任務風險、可逆性與影響範圍決定控制強度。

1. Prompt｜意圖

要回答的問題

• 任務的真正目標是什麼？

• 讀者、使用者或受影響對象是誰？

• 哪些條件不可改變？

• 什麼叫完成？

應留下的產物

• 任務說明

• 輸入與背景

• 完成條件

• 禁止事項

• 範例與反例

警訊

• 目標只能用「做得好一點」描述

• 指令彼此衝突

• 把法律、權限或安全規則只寫成請求語氣

2. Tool｜工具與權限

要回答的問題

• Agent 可以讀什麼、寫什麼、執行什麼？

• 哪些工具會產生不可逆影響？

• 是否有沙盒、最小權限與回退？

應留下的產物

• 工具清單

• 權限矩陣

• 沙盒或分支策略

• 速率、成本與重試限制

警訊

• Agent 使用管理員權限完成一般任務

• 讀寫範圍沒有邊界

• 工具失敗後無限重試

3. Workflow｜工作流

要回答的問題

• 任務有哪些狀態、步驟、分支與依賴？

• 哪裡可以暫停與恢復？

• 哪一步由 D、I、H 或 A 負責？

應留下的產物

• 流程圖或狀態圖

• 工作流定義與實例

• 檢查點

• 工作流護照

警訊

• 只保留最終成果

• 失敗後只能全部重來

• 無法知道哪一步產生某個結果

4. Memory｜記憶

要回答的問題

• 哪些早期資訊必須持續影響後續決策？

• 什麼事件會觸發提醒？

• 何時應保持沉默？

• 記憶何時過期、修正或刪除？

應留下的產物

• 結構化記憶項目

• 觸發條件

• 來源與有效期

• 提醒與未提醒紀錄

警訊

• 所有歷史永遠塞進 Prompt

• 重要限制只存在於長對話深處

• 過期資訊沒有版本與失效機制

5. Contract｜契約

要回答的問題

• 哪些規則不能交給模型自由判斷？

• 輸入、輸出、來源與敏感資訊有哪些硬性邊界？

• 違規輸出如何攔截與記錄？

應留下的產物

• Schema

• Manifest

• Validator

• 來源與實體路由

• 違規處理政策

警訊

• 「請勿洩漏」是唯一防線

• 換模型後規則跟著消失

• 無法說明哪一條契約被觸發

6. Eval｜評估

要回答的問題

• 正確、完整、安全與完成分別怎麼定義？

• 哪些項目可以用程式測試？

• 哪些項目需要 Rubric、第二模型或人？

• 失敗後要重試、回退還是升級？

應留下的產物

• 單元測試與整合測試

• Rubric

• 對照樣本

• 風險門檻

• 失敗報告

警訊

• 只用「看起來不錯」驗收

• Agent 自己宣布完成就是完成

• 平均分數掩蓋高風險失敗

7. Crystallization｜固化

要回答的問題

• 哪些路徑已反覆成功？

• 哪些步驟仍需要語意判斷？

• 升級成固定流程需要多少證據？

• 環境改變時如何降級？

應留下的產物

• 成功軌跡

• 候選模板或腳本

• Promotion Gate

• 回退條件

• 版本與成本比較

警訊

• 已知流程仍每次重新推理

• 只因一次成功就過早固化

• 固化後沒有偏移監控

8. Governance｜治理

要回答的問題

• 哪些資料、模型與版本被允許？

• 誰負責批准、監控與事件處理？

• 保存、刪除、稽核與責任政策是什麼？

應留下的產物

• 風險分級

• RACI／責任矩陣

• 資料生命週期政策

• 模型與提示版本

• 事件處理與稽核紀錄

警訊

• 沒有人對整體結果負責

• 高風險與低風險任務使用相同控制

• 無法重建某次決策的依據

9. Human on Loop｜人工監督

要回答的問題

• 哪些情況需要人批准？

• 哪些警訊出現時要暫停或接管？

• 人看到哪些資訊才足以做決定？

• 人工修改如何回饋流程？

應留下的產物

• 批准點

• 升級與接管路徑

• 停止開關

• 值班或責任角色

• 修改與回饋紀錄

警訊

• 人只在事故發生後才知道

• 每一步都要人按同意，形成假自動化

• 人批准時看不到來源、版本與風險
