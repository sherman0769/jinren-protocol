終章｜Loop Engineering：人不是在迴路裡救火，而是在迴路上方設計系統

人不是每一步都插手，而是設計一套讓 AI 能做事、能被限制、能被驗證、能被接管、能被追責的工作流。

一、這一章要解決的問題

一本談 Agent 的書，如果最後只留下更多工具與名詞，就沒有真正回答最重要的問題：

當 AI 已經可以規劃、使用工具、保存狀態、產生內容、修改程式與承接長任務，人應該站在哪裡？

有一種做法，是人守在每一步旁邊。

Agent 讀一個檔案，人確認；呼叫一次工具，人確認；產生一段內容，人再確認。這種 Human in the Loop 在高風險情境很有必要，但如果每一個低風險動作都必須等人，系統只是把手動工作換成更多按鈕。

另一種做法，是完全放手。

只給目標與權限，讓 Agent 自己探索、自己判斷、自己發布。這能展示速度與自主性，卻可能在錯誤假設、遺忘、越權與驗證不足時，把問題一路放大到正式系統。

真正成熟的設計，不在兩個極端之間選一邊。

它會先判斷：

• 哪些事情可以自動前進？

• 哪些事情要由程式攔截？

• 哪些事情需要人工批准？

• 哪些情況應回退到更有彈性的模式？

• 哪些成功路徑已經可以固化？

• 哪些指標代表系統正在偏離？

這就是本書所說的 Loop Engineering。

它處理的不只是怎麼叫 AI 做事，而是怎麼設計一個能持續工作、持續被觀察、持續被改善，也能在風險升高時被人接管的迴路。

二、用白話講清楚核心技術

Loop Engineering 在 2026 年的 Agent 實務社群中，已被用來描述人從逐次提示者轉向迴路設計者的工作方式。本書不把它宣稱為已完成的產業標準，而是整合十篇研究與實務觀察，建立一套九層工作框架。

可以把它想成自動駕駛車隊。

駕駛不需要每一秒轉動方向盤，但系統需要地圖、感測器、道路規則、風險監控、煞車、行車紀錄、遠端接管與持續更新。真正的工程不在一句「開到目的地」，而在整套讓車能安全前進的迴路。

第一層：Prompt｜意圖層

Prompt 說明目標、背景、限制與輸出形式。

核心問題是：

Agent 現在被要求完成什麼？

常見失敗是目標模糊、條件互相衝突，或把不可違反的規則只寫成自然語言期待。

應交付的產物包括任務說明、完成定義、讀者與語氣、例子與禁止事項。

第二層：Tool｜行動層

Tool 讓 Agent 從回答走向行動。

核心問題是：

Agent 可以接觸哪些資源，能造成什麼影響？

常見失敗是權限過大、工具沒有隔離、讀寫範圍不清、外部服務錯誤沒有處理。

應交付的產物包括工具清單、權限矩陣、沙盒策略、重試與失敗政策。

第三層：Workflow｜流程層

Workflow 把任務拆成狀態、步驟、依賴、分支與停止條件。

核心問題是：

任務如何從現在的狀態前進到完成？

第一章提醒我們，工作流本身也應被保存成知識：不只留下成果，也留下實例、上下文、推論、批准與依賴。（R01）

應交付的產物包括工作流定義、工作流實例、檢查點與工作流護照。

第四層：Memory｜記憶層

Memory 保存長任務中需要持續影響決策的狀態。

核心問題是：

什麼資訊必須在什麼時刻重新出現？

第二章提醒我們，資訊存在不等於資訊仍有行為效果；主動記憶需要選擇性提醒，也要知道何時沉默。（R02）

應交付的產物包括結構化記憶、觸發條件、提醒紀錄與過期政策。

第五層：Contract｜契約層

Contract 把不可違反的規則放進程式、Schema、Validator、Manifest、路由與輸出邊界。

核心問題是：

哪些要求不能只靠模型自律？

第三章提醒我們，Prompt 表達意圖，Harness 才能在模型失誤時攔住可程式檢查的違規輸出。（R03）

應交付的產物包括輸入輸出 Schema、來源邊界、敏感資訊規則、驗證器與違規處理。

第六層：Eval｜評估層

Eval 定義正確、完整、安全與完成。

核心問題是：

我們憑什麼相信這一步可以進入下一步？

不同任務需要不同證據：單元測試、資料驗證、Rubric、對照樣本、第二模型審查、人工抽查或專業放行。

第五章的 Bug Report 研究也顯示，清楚的預期行為、重現方式、位置資訊與結構，會直接影響 Agent 是否有可驗證的解題路徑。（R05）

應交付的產物包括測試、驗收條件、評分規則、風險門檻與失敗報告。

第七層：Crystallization｜固化層

Crystallization 把反覆成功的探索路徑，逐步轉成穩定、可重播的流程。

核心問題是：

哪些步驟已經不需要每次重新推理？

第四章提醒我們，Agent 適合未知與例外；成功路徑累積足夠證據後，可以升級成混合或確定性流程，環境改變時也要能降級。（R04）

應交付的產物包括軌跡樣本、候選模板、Promotion Gate、回退條件與版本紀錄。

第八層：Governance｜治理層

Governance 管理資料、模型、權限、審計、責任與生命週期。

核心問題是：

誰被允許做什麼，出事時如何追溯與負責？

教育研究提醒我們，使用率不能取代成效與公平性；健康研究提醒我們，辨識能力不能直接升級成高風險責任。（R08、R09）

應交付的產物包括風險分級、責任矩陣、資料保存與刪除政策、模型版本與事件處理流程。

第九層：Human on Loop｜人類監督層

Human on Loop 不是人消失，也不是每一步都手動批准。

核心問題是：

人要在什麼層級設計、觀察、批准、暫停與接管？

第十章顯示，AI 工作單位正在從回答走向較長的委派任務。當多個 Agent 與長任務出現，人更像任務與風險的管理者。（R10）

應交付的產物包括批准點、升級路徑、停止開關、人工接管程序與責任人。

九層不是一次建滿，而是依風險組合

一篇低風險的社群草稿，不需要和醫療建議使用相同治理強度。

但它仍可能需要來源檢查、版本保存與人工發布。

一個會修改正式資料庫的企業 Agent，則需要更嚴格的工具權限、契約、測試、批准與回退。

Loop Engineering 的重點不是把系統做得最複雜，而是讓控制強度與任務風險相配。

三、論文真正想提醒我們什麼

把十個來源放在一起，可以看見一條共同的技術路線。

Agent 能做更多之後，過程必須被保存

Workflow as Knowledge 把執行過程從暫時 Log 提升成可查詢的知識物件。（R01）

任務拉長之後，記憶必須有時機

Proactive Memory Agent 不是把所有歷史塞進 Prompt，而是在行動即將受影響時提供最小必要提醒。（R02）

進入企業之後，規則必須成為可執行契約

Harness Engineering 把來源、格式、敏感資訊與禁止行為放進模型外部的程式層。（R03）

路徑成熟之後，探索必須逐步固化

Progressive Crystallization 讓系統不必永遠支付 Agent 的推理成本，也保留環境改變時的回退能力。（R04）

任務委派之前，交接必須結構化

Bug Report 研究顯示，問題的可重現性、定位與格式，會影響 Agent 解題表現。（R05）

AI 進入新模態後，仍然需要中間狀態與限制

OpenCoF 把影片看成可承載時間與因果的推理過程；ARDY 讓人體動作生成走向即時控制，但兩者都不代表系統已經自動取得人類理解或安全保證。（R06、R07）

AI 進入教育與健康後，使用與感知不能取代成效與責任

Syntea 的使用 Log 能描述採用，不能單獨證明學習；OmniFood-Bench 顯示語意辨識不能直接外推到物理量與安全建議。（R08、R09）

工作單位變大之後，人需要管理整條任務

Codex 使用研究讓我們看見，Agent 正從短答題走向長任務與並行工作。（R10）

這些論文沒有共同宣布一個叫 Loop Engineering 的標準。

本書做的是研究編輯與架構整合：把分散的技術發現，整理成一條可以被教學、導入與持續改進的系統主張。

四、這個技術如何改變 AI 教學

未來的 AI 課程可以分成三個階段。

第一階段：會使用模型

學會寫清楚需求、選擇模型、提供上下文、判讀輸出。

第二階段：會建立工作流

學會工具串接、狀態保存、檢查點、驗收、錯誤處理與檔案交付。

第三階段：會設計迴路

學會記憶觸發、契約、風險分級、人工批准、漸進式固化與治理。

課程作業也應從「產生一個成果」變成「交付一條可運作的迴路」。例如：

• 任務規格

• 流程圖

• D／I／H／A 標記

• 權限與資料邊界

• 測試與 Rubric

• 失敗案例

• 人工批准點

• 固化候選

• 最終成果與執行證據

學生真正要學會的，不是把每件事交給 AI，而是判斷每一件事應該由模型、程式、工具還是人負責。

五、這個技術如何改變企業導入

企業不應從「買哪一個 Agent 平台」開始，而應先選一條真實工作流，回答九層問題。

第一步：選擇邊界清楚的任務

有可觀察輸入、可定義輸出、可建立驗收，而且錯誤可回退。

第二步：先保留完整軌跡

讓組織看見 Agent 如何工作、哪裡失敗、哪些例外反覆出現。

第三步：把高風險規則移出 Prompt

來源、權限、格式、敏感資訊與批准條件，改成程式與政策。

第四步：建立評估與事件處理

不只測平均品質，也測最壞情境、拒絕、越界、資料缺漏與工具失敗。

第五步：從成功軌跡提取固定流程

把穩定部分轉成 Script、API、Schema 與固定 Pipeline，保留 Agent 處理未知與例外。

第六步：讓人站在風險與改善迴路上

主管與專家關注例外、趨勢、批准、回退與流程升級，而不是人工重做每一個普通步驟。

企業的 Agent 成熟度，可以用本書提出的五個階段觀察。這是本書的工作模型，不是產業標準。

Level 0｜聊天輔助

AI 產生內容，人逐次操作，沒有正式工作流。

Level 1｜工具型 Agent

AI 能呼叫工具與完成短任務，但狀態與驗收仍零散。

Level 2｜可觀察工作流

有結構化步驟、軌跡、檢查點與可重跑能力。

Level 3｜可治理迴路

有記憶、契約、評估、權限、人工批准與事件處理。

Level 4｜適應與固化

系統能根據證據升級固定流程、處理偏移、回退到 Agent 探索，並持續改善。

成熟不是 Agent 參與得愈多愈好。

成熟是每一種工作都由最適合、最可靠、最可負責的機制處理。

六、連到李詩民的實際場景

建立「每日出本書」的出版迴路

你可以把寫書系統拆成：

1. 接收語音與想法

2. 建立 Book Bible

3. 鎖定章節任務

4. 查證研究

5. 逐章撰寫

6. 去重與名詞校正

7. 合併 Markdown

8. 產生 DOCX

9. 視覺與檔案驗證

10. ZIP 打包與交付

在這條迴路裡：

• 作者觀點與真實經驗由人提供或確認。

• 論文事實由研究流程查核。

• 格式、字數與檔案存在由程式驗證。

• 重複、語氣與論證由模型與人共同編輯。

• 正式交付必須經過檔案測試。

這不是「讓 AI 自己寫一本書」，而是建立一套能保留思想主軸、研究證據與出版品質的協作系統。

建立內容自動化迴路

研究 Agent 只負責來源與事實；文案 Agent 只使用已批准的研究摘要；影音 Agent 使用鎖定文案；發布前由契約檢查平台欄位與禁用內容；人批准後才對外發布。

成功跑過的檔名、字幕、轉檔與發布欄位逐步固化。真正需要創意與例外判斷的部分，才留給 Agent。

建立健身 AI 迴路

學員輸入狀態，記憶系統在相關動作前喚回傷病與限制；運動規則檢查禁忌；AI 提供候選課表；教練在高風險或新情境下批准；執行資料回到評估；穩定的紀錄與提醒流程固化。

建立美髮 AI 迴路

顧客歷史、過敏與漂髮次數不只是聊天紀錄，而是結構化記憶；配方輸出受欄位與材料契約限制；高風險狀況要求設計師確認；實際結果與不良反應回饋下一次決策。

建立企業內訓主張

你可以把課程從「Prompt Engineering」一路講到「Loop Engineering」：

• Prompt 是意圖介面。

• Tool 是行動能力。

• Workflow 是任務結構。

• Memory 是狀態持續性。

• Contract 是系統保證。

• Eval 是通過證據。

• Crystallization 是成本與穩定性策略。

• Governance 是組織責任。

• Human on Loop 是人的新位置。

這會形成一套可以跨內容、程式、教育、健康與企業場景使用的方法論。

七、可以轉成課程的一句話

Prompt Engineering 解決怎麼叫 AI 做事；Loop Engineering 解決 AI 做事之後，如何被記憶、限制、驗證、接管、固化與追責。

八、可以轉成 FB 貼文的一段話

Agent 時代，我們真正要學的可能不再只是 Prompt Engineering，而是 Loop Engineering。Prompt 解決的是「怎麼叫 AI 做事」，Loop 解決的是「它做事之後，怎麼留下狀態、記住重要條件、遵守程式契約、通過驗收、在高風險時讓人接管，成功後再把流程固化」。人不是退出迴路，也不是每一步都在裡面救火；人要站到迴路上方，設計權限、檢查點、停止條件與責任。Agent 負責探索，系統負責記憶、約束、驗證與固化。

九、這章的延伸問題

1. 九層中，哪一層是目前多數 Agent 專案最常缺少的？

2. 如何依任務風險決定人工批准的頻率？

3. Human on Loop 需要哪些新的管理儀表板與事件資訊？

4. 何時應讓流程從 Agent 模式升級成確定性模式？

5. 如何避免固化後的流程因環境改變而悄悄失效？

6. 哪些評估適合自動化，哪些必須保留專家判斷？

7. 如何讓組織對 Agent 錯誤負責，而不只是把責任推給模型？

8. Loop Engineering 如何成為可教學、可評量與可認證的專業能力？

9. 當 Agent 彼此呼叫形成更大的系統時，誰負責全局狀態與停止權？

李詩民式總結

寫到最後，我真正想留下的不是十篇論文摘要，也不是九個新名詞。

我想留下的是一個看待 Agent 的角度。

不要只問它會不會做。

還要問它做過的事能不能留下來、重要的條件會不會在正確時刻被想起來、規則能不能真的攔住、結果有沒有證據、成功的路徑能不能被系統接手、失敗時人能不能接管。

AI 愈能做事，人愈不能只當提問者。

我們要成為迴路的設計者。

Agent 可以探索、生成、嘗試與處理例外。

系統負責記憶、約束、驗證、固化與治理。

人站在迴路上方，決定方向、風險、責任與什麼值得留下。

這就是從 Prompt Engineering 走向 Loop Engineering 的真正意義。

章末金句

1. Agent 負責探索，系統負責記憶、約束、驗證與固化。

2. 人不必待在每一步裡，但必須站在整個迴路之上。

3. 自動化的成熟，不是人完全消失，而是人的介入變得有目的。

4. Prompt 是一次要求，Loop 是持續責任。

5. 模型會更新，工具會替換，可靠的迴路才能累積成組織能力。

6. 讓 AI 自由工作之前，先設計它如何被停止與接管。

7. 成功一次是能力展示，成功可重現才是系統。

8. 最好的 Agent 系統，不是每一步都用 AI，而是每一步都由最適合的機制負責。

9. AI 的未來不只在模型參數裡，也在我們如何設計工作迴路。

10. 從 Prompt Engineering 到 Loop Engineering，是從會使用 AI，走向會對 AI 的工作負責。
