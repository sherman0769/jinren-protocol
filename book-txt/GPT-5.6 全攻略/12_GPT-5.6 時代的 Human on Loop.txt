GPT-5.6 時代的 Human on Loop

章首開場：人不是要從工作中消失，而是要換一個位置

每一次 AI 能力提升，都會帶來同一個焦慮：人還要做什麼？

如果模型能研究、寫作、做簡報、操作電腦、建立網站、修改程式、協調多 Agent，人的價值是不是只剩下按下開始？

這個問題把「工作」想得太像一串手動步驟。當工具接手步驟，人並不必然失去價值；人可以移到更高的位置，設計目標、邊界、資源、驗收、例外與改善。

這就是 Human on Loop。

Human in the Loop 是人在流程中核准或補足；Human on Loop 是人站在整個循環之上，觀察系統是否朝正確方向前進，並在必要時介入。前者關注一次動作，後者關注整個工作系統。

人不必卡在每一個步驟裡，但必須看得見整個循環，並對方向與後果負責。

一、從 Chatbot 到 Loop：五個階段的工作演化

Stage 1：Chatbot——回答

人提出問題，AI 回答。工作價值集中在一次互動。

Stage 2：Agent——行動

AI 能使用工具、讀取資料、修改檔案與執行任務。工作價值從答案擴大到行動。

Stage 3：Work——工件

AI 能蒐集 Context、規劃、跨工具工作，建立文件、試算表、簡報、程式與網站。工作價值擴大到可交付成果。

Stage 4：Runtime——運行

模型、Context、工具、狀態、權限、觀察與評估形成可持續運作的環境。工作不再依賴每次從聊天視窗重新開始。

Stage 5：Loop——改善

成果進入真實世界，產生使用資料、錯誤、回饋與新需求，再回到系統，讓下一次更好。

這五個階段不是產品版本，而是使用成熟度。一個人即使使用最強模型，若每天仍在複製貼上，也可能停在 Stage 1；一個團隊使用較低成本模型，卻有穩定 Runtime 與 Evals，反而進入 Stage 5。

二、Human-in、Human-on、Human-out：三種人機位置

Human-in-the-Loop

人出現在流程裡，負責核准、分類、判斷或補資料。適合高風險、低信心與需要價值判斷的節點。

Human-on-the-Loop

系統大部分時間自行運作，人透過儀表板、告警、抽樣、週期審查與政策管理監督。適合已穩定、可觀察、可回復的重複流程。

Human-out-of-the-Loop

系統完全自動運作，人不參與當次決定。只適合低風險、規則清楚、可逆、已充分測試的工作；即使如此，仍需要有人負責系統生命週期。

成熟的設計不是選一種，而是把不同節點放在適當位置。資料清理可能 Human-out；公開發布 Human-in；整體品質與成本 Human-on。

三、Human on Loop 的六個控制面

我把人的上層責任整理成 HOL Control Plane。

1. Outcome——成果控制

這個循環服務什麼人？要改善什麼結果？完成標準是什麼？

2. Policy——政策控制

哪些資料、行動與用途允許？哪些需要核准？哪些禁止？

3. Context——情境控制

系統使用哪些來源、版本與記憶？哪些資料過期、矛盾或不應進入？

4. Portfolio——工作組合控制

哪些任務交給 Luna、Terra、Sol、單一 Agent、多 Agent、程式或人？資源如何配置？

5. Telemetry——觀察控制

如何看見品質、成本、延遲、錯誤、拒絕、人工介入與使用者結果？

6. Intervention & Learning——介入與學習

什麼訊號觸發停止、降級、回復、人工接手或政策更新？每次失敗如何變成新 Eval、Skill 或 Guardrail？

這六個控制面讓 Human on Loop 不只是口號，而是可以被設計的管理介面。

四、Loop Engineering：流程把事情做完，循環讓事情變好

流程（Process）描述從 A 到 B 的步驟；循環（Loop）還包含感測、比較、修正與記憶。

一個完整 AI Loop 至少有七個元件：

1. Goal：要達成的結果。

2. Context：理解現場所需的世界。

3. Action：模型、工具與人執行工作。

4. Artifact：可檢查的成果。

5. Sensor：收集測試、使用者回饋、錯誤與指標。

6. Evaluator：比較成果與標準。

7. Memory：把有效改進保留下來。

沒有 Sensor，系統不知道發生什麼；沒有 Evaluator，資料只是一堆數字；沒有 Memory，每次都重新犯錯。

Loop 的基本式

```text下一次能力= 本次能力+ 被看見的偏差+ 被驗證的修正+ 被保存的經驗```

AI 能提高 Action 速度，但 Loop Engineering 決定速度是否轉成長期能力。

五、Human on Loop 不是「人最後看一下」

很多流程把人放在最後一關，收到一份已經完成的巨大成果，只能按核准或退回。這不是真正的 Human on Loop，因為介入太晚、資訊太少。

有效的人類監督需要：

- 在開始前決定 Outcome 與邊界。

- 在高風險轉折前取得核准。

- 在執行中看到異常與成本。

- 在結束後看到證據、差異與限制。

- 在週期層面看到趨勢與回歸。

- 能把決定寫回政策、Skill 與 Eval。

人的介入點應像交通號誌，而不是終點站的保全。

六、Decision Rights Matrix：誰有權決定什麼？

AI 導入最常見的模糊不是技術，而是責任。可以建立 Decision Rights Matrix。

| 決策類型 | AI 可建議 | AI 可執行 | 人需核准 | 最終責任 ||---|---|---|---|---|| 公開資料摘要 | 是 | 是 | 抽樣 | 內容 Owner || 內部草稿 | 是 | 是 | 視分級 | 任務 Owner || 正式對外發布 | 是 | 準備發布 | 是 | 授權發布者 || 客戶資料修改 | 是 | 受限執行 | 是或政策化 | 資料 Owner || 支付款項 | 可分析 | 不直接 | 必須 | 財務授權者 || 醫療／法律最終決定 | 可輔助 | 不取代專業決策 | 必須 | 合格專業人員 || 模型路由調整 | 可提出 | 沙箱測試 | 生產變更需核准 | AI 系統 Owner |

矩陣不是為了增加文件，而是避免出事後大家才問「誰以為 AI 可以這樣做？」

七、Loop Literacy：下一代 AI 素養不是會寫 Prompt

我把 Human on Loop 所需能力稱為 Loop Literacy，循環素養。它包含八種能力。

1. Outcome Literacy

能把模糊願望轉成成果、受眾、交付物與驗收。

2. Context Literacy

知道模型需要什麼世界，也知道什麼資料不應該給。

3. Model Literacy

理解能力、成本、推理層級與路由，不迷信單一最強模型。

4. Tool Literacy

知道工具是行動介面，權限、Schema、錯誤與冪等都會影響可靠性。

5. Evaluation Literacy

能建立代表性案例、Rubric、指標與回歸，而不是只憑一次驚豔判斷。

6. Risk Literacy

辨認資料、權限、不可逆動作、Prompt Injection、隱私與責任。

7. Orchestration Literacy

知道何時單 Agent、何時多 Agent、何時程式、何時人類更適合。

8. Learning Literacy

能把失敗轉成制度資產：更新 Context、Skill、工具、政策或 Eval。

會 Prompt 是入口；會設計循環，才是工作能力。

八、Human on Loop Dashboard：人應該看什麼？

一個 Loop Owner 不需要閱讀每段模型輸出，但要看見關鍵指標。

Outcome

- 任務完成率。

- 使用者成功率。

- 工件通過率。

- 人工返工時間。

Quality

- 事實錯誤。

- 必要證據保留。

- 格式與可用性。

- 不同群體品質差異。

Operations

- 延遲。

- 成本。

- 失敗與重試。

- 工具可用率。

- Agent 阻塞。

Risk

- 越權嘗試。

- 敏感資料事件。

- 外部寫入核准。

- 安全拒絕與異常。

- Prompt Injection 告警。

Learning

- 新增 Eval 數。

- 已修復重複失敗。

- Skill 版本與採用率。

- 模型或政策變更後的回歸。

儀表板的目的不是製造更多數字，而是幫助人決定：繼續、調整、暫停或擴大。

九、Exception Budget：不要追求沒有例外，而要管理例外

現實工作永遠有例外。若要求 Agent 處理所有特殊情況，系統會變得複雜、危險；若遇到任何例外都失敗，又沒有價值。

可以建立 Exception Budget，例外預算：

- 哪些例外由 Agent 依政策處理？

- 哪些轉人工？

- 每週可接受多少人工介入？

- 什麼例外出現三次後，值得改進系統？

- 哪些低頻高風險例外永遠保留人工？

例如課程報名系統可自動處理一般候補，但特殊減免、個資更正與爭議退款轉人工。當某種人工例外持續增加，才評估是否納入下一版。

這避免為了極少數情況把整個 Runtime 過度工程化。

十、Loop Debt：沒有被保存的修正，會變成下一次的重工

我們在前面談過 Outcome Debt 與 Artifact Debt。更高一層的是 Loop Debt，循環債。

Loop Debt 的症狀：

- 每次遇到相同錯誤，都靠人提醒。

- 有回饋，卻沒有更新 Prompt、Skill 或 Eval。

- 模型升級後沒有回歸測試。

- 工具壞了只重啟，不找根因。

- 最懂流程的人離開，系統知識一起消失。

- 儀表板有很多指標，沒有人採取行動。

償還 Loop Debt 的方法，是替每次重要失敗建立「學習去向」：

- 資料問題 → Context 與來源治理。

- 行為問題 → Policy 或工具邊界。

- 格式問題 → Schema 或 Artifact Test。

- 品質問題 → Eval、模型或 reasoning 設定。

- 重複工作 → Skill 與自動化。

- 高風險例外 → Approval Gate 或人工流程。

一個錯誤只有在改變下一次系統時，才真正被解決。

十一、個人 AI Runtime：講師、架構師與內容創作者如何開始

Human on Loop 不只適用大型企業。個人也可以建立自己的 Runtime。

Intake——輸入層

語音想法、Email、會議、照片、文件、連結與待辦，先進入統一收件匣。

Context——情境層

個人定位、寫作風格、課程架構、協會資料、品牌、常用案例與專案狀態，整理成可重用 Context Pack。

Agent Portfolio——工作層

- 研究 Agent：找官方資料與新趨勢。

- 編輯 Agent：重整口語想法。

- 書稿 Agent：發展長文與模型。

- 工件 Agent：做 DOCX、簡報、試算表。

- Codex Agent：建立工具與網站。

- 驗收 Agent：檢查事實、版面與交付清單。

Artifact Store——成果層

每個專案都有固定資料夾、命名、版本、README、來源與可下載包。

Review Rhythm——審查節奏

- 每日：看待決策事項。

- 每週：看卡住任務、成本與重複錯誤。

- 每月：更新 Skill、課程、品牌與 Eval。

- 每季：決定哪些工作擴大自動化，哪些停止。

這不是一定要買一套龐大系統，而是把你的工作經驗從腦中搬進可持續循環。

十二、從一場演講建立內容循環

以「GPT-5.6 全攻略」演講為例：

1. 研究 Agent 追蹤官方更新。

2. Context Agent 將新資料映射到十二章模型。

3. 編輯 Agent 更新講稿與簡報。

4. 工件 Agent 渲染並檢查投影片。

5. 演講後收集問題、回饋與停留點。

6. 分析 Agent 找出最難理解與最有共鳴段落。

7. 人決定哪些觀點修正、哪些案例加入。

8. 更新書稿、課程、短文、FAQ 與下一場演講。

這時，一場演講不是一次性輸出，而是一個知識感測器。聽眾問題成為下一輪 Context，書與課程因此一起進化。

十三、從一本書建立出版循環

一本書也可以有 Runtime：

- Stable Core：穩定思想、核心模型與章節。

- Update Layer：產品、價格、介面與政策的最新頁。

- Teaching Layer：演講、簡報、練習與課程。

- Community Layer：讀者案例、問題與回饋。

- Eval Layer：哪些概念被理解、哪些案例有效。

- Revision Layer：新版、勘誤與延伸內容。

紙本或 DOCX 提供穩定深度，網站與社群提供更新速度。Agent 負責整理，人負責決定思想主軸與出版責任。

十四、組織導入的 30／60／90 天路線

前 30 天：找一個可觀察的小循環

- 選擇高頻、可逆、資料風險可控的工作。

- 記錄目前時間、錯誤與人工成本。

- 建立 Outcome Contract 與 20～50 個真實 Eval 案例。

- 先用單一 Agent 與最小工具。

- 所有成果維持草稿與人工核准。

31～60 天：建立 Runtime

- 加入 Model Router、Context Pack、工具契約與 Trace。

- 將重複方法封裝為 Skill。

- 建立資料與動作分級。

- 用 Artifact Tests 與 Evals 做回歸。

- 計算每個通過成果的成本。

61～90 天：站上循環

- 對穩定低風險步驟降低人工介入。

- 只在高風險與低信心節點保留核准。

- 建立 Human on Loop Dashboard 與事件流程。

- 依真實資料決定是否引入多 Agent。

- 指定 Loop Owner，建立每月改進節奏。

90 天的目標不是「全公司都用 AI」，而是證明一個循環能被看見、被控制、被改善，再複製方法。

十五、AI Operating Model：技術之外，組織要有四種角色

Outcome Owner

對業務結果負責，決定什麼叫成功。

Runtime Owner

對模型、Context、工具、狀態與服務運作負責。

Risk Owner

對資料、權限、法規、安全與事件負責。

Learning Owner

對 Evals、回饋、Skill 與持續改善負責。

小團隊可以由同一人兼任，但責任不能消失。當大家都說「這是 AI 做的」，通常代表沒有真正的 Owner。

十六、GPT-Live：即時互動是入口，深度工作仍要進入 Runtime

2026 年 7 月 8 日推出的 GPT-Live 強調自然即時語音、插話、搜尋、記憶與多模態互動；官方在推出時也說明，較深工作的委派會交由後端更適合的模型處理。[OAI-15]

這讓 Human on Loop 多了一個重要入口：人可以用口語描述現場、補充 Context、聽取狀態與下達核准，不必一直盯著表單與儀表板。

但語音介面不等於治理。即時對話適合意圖與協調，正式工作仍要落到可追蹤的任務、工件、權限與驗收。

Voice 是人進入 Runtime 的自然入口；Loop 才是工作持續變好的地方。

十七、未來競爭力：不是誰擁有最強模型，而是誰擁有最好的循環

模型能力會快速擴散，價格會改變，介面會更新。今天的領先模型，明天可能成為一般能力。若競爭力只建立在「我們比較早用到某個模型」，優勢很短。

更持久的資產是：

- 你對工作與客戶的獨特理解。

- 乾淨、可授權、可追溯的 Context。

- 經過驗證的 Outcome Contract。

- 好用且安全的工具。

- 真實失敗累積成的 Eval Set。

- 團隊共同的 Skill 與工件標準。

- 快速從回饋更新系統的節奏。

這些共同形成 Loop Moat，循環護城河。模型人人可以買，循環必須在工作中長出來。

十八、給個人的行動清單：明天開始改變一個工作

不要先問「我要如何全面導入 GPT-5.6？」先選一件每週重複、令人厭煩、成果可檢查的工作。

1. 寫出目前輸入、步驟、成果與錯誤。

2. 定義一份 Outcome Contract。

3. 整理最小 Context Pack。

4. 決定哪些步驟交給模型、程式或人。

5. 只接必要工具。

6. 保持成果為草稿，先跑十次。

7. 記錄每次人工修改與失敗。

8. 將前三個重複問題變成規則或 Eval。

9. 達到穩定後，再放寬一個可逆步驟。

10. 每月問：這個循環真的讓結果變好，還是只是讓產量變大？

Human on Loop 的起點，不是一個宏大架構，而是人第一次把工作當成可以被觀察與改進的系統。

十九、結語：站在循環之上

ChatGPT 的第一個時代，教我們如何跟 AI 說話；GPT-5.6 所代表的新階段，要求我們學會如何替 AI 建立工作世界。

這個世界包含 Context、工具、資料、權限、工件、Agent、Trace、Evals、Guardrails 與人。任何單一元件都不是答案。真正的能力，是讓它們形成循環：有目標、有行動、有感測、有判斷、有修正，也有人願意承擔方向與後果。

我們不需要在每一個步驟證明人比 AI 聰明，也不需要把所有決定交給 AI 才叫自動化。人的位置可以更高、更清楚：定義什麼值得完成，決定什麼不能被犧牲，在系統偏離時介入，在經驗出現時把它保存。

Chatbot 的問題是「AI 能回答什麼？」Agent 的問題是「AI 能做什麼？」Runtime 的問題是「AI 在什麼世界工作？」Human on Loop 的問題是「我們要讓這個世界朝哪裡前進？」

GPT-5.6 全攻略的終點，不是掌握所有功能，而是建立一種新的工作觀：讓 AI 接手可以被定義的行動，讓人站在循環之上，守住目的、責任與持續改善。

二十、章末金句

1. 人不是要從工作中消失，而是要換一個位置。

2. 人不必卡在每個步驟裡，但必須看得見整個循環。

3. Chatbot 回答，Agent 行動，Work 交付，Runtime 運行，Loop 改善。

4. Human-in-the-Loop 管一次決定；Human-on-the-Loop 管整個系統。

5. 流程把事情做完，循環讓事情變好。

6. 沒有 Sensor，系統不知道偏差；沒有 Memory，系統只會重複犯錯。

7. 人的介入點應像交通號誌，而不是終點站的保全。

8. 會 Prompt 是入口；會設計循環，才是工作能力。

9. 一個錯誤只有在改變下一次系統時，才真正被解決。

10. 一場演講可以是知識感測器，一本書可以是一個持續更新的 Runtime。

11. 模型人人可以買，循環必須在工作中長出來。

12. 未來的競爭力，不是擁有最強模型，而是擁有最好的循環。

13. Voice 是人進入 Runtime 的自然入口；Loop 才是工作持續變好的地方。

14. 人站在循環之上，不是為了控制每一步，而是為了守住方向與責任。

15. GPT-5.6 的終點不是功能全會，而是工作系統開始會學習。
